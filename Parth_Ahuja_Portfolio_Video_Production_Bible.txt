1. Core Video Strategy

The recommended format is a hybrid presenter documentary: the AI avatar appears only when a human-style introduction or transition adds value. The project itself should occupy most of the screen through PPT slides, browser capture, diagrams, dashboards and evidence.

Layer

What viewer sees

Recommended ratio

AI presenter

Avatar introducing the project, transitions, conclusion

10-20%

Slides / diagrams

Problem, strategy, architecture, decisions, results

25-35%

Real product

Website, dashboard, app, live demo walkthrough

35-50%

Evidence overlays

GitHub, report, metrics, screenshots, citations

10-15%

Why this format: a pure talking avatar can look like training content; a pure screen recording can feel dry. Combining the presenter with real proof makes the video both attractive and credible.

Free-first principle

6. Exact Production Workflow

1. Collect the verified project content and URLs from the portfolio CMS.

2. Use AI only to draft the first script from approved project data; human-review every claim.

3. Build the project PPT from the standard slide template.

4. Record the actual website/app walkthrough in OBS at 1920x1080, 30fps unless the project requires otherwise.

5. Capture supporting browser states: landing page, key feature, dashboard, output/result, GitHub or documentation screen.

6. Generate the AI-avatar hook, one transition and one outro. Keep avatar segments short.

7. Assemble in CapCut/Canva using the standard timeline template.

8. Add captions and manually correct names, technical terms and URLs.

9. Insert evidence overlays while the related claim is being discussed.

10. Add chapter markers and end screen with Live / GitHub / Document / Portfolio.

11. Export 16:9 master at 1080p; create 9:16 and 60-90 second derivatives from the same master.

12. Upload to video hosting / YouTube and store canonical embed/URL metadata in the project record.

13. Update the portfolio project page with poster, video URL, transcript, chapters and last-verified date.

8. AI Script Generation Prompt System

Store one approved master prompt for generating project scripts from structured portfolio data. The assistant must only use supplied facts and must flag missing information.

Master script prompt

SYSTEM / SCRIPT WRITER

You are writing a portfolio project explainer for Parth Ahuja. Use ONLY the approved project data supplied in the input. Do not invent metrics, dates, employers, technologies, user counts, benchmarks or outcomes. If a fact is missing, write [NEEDS VERIFICATION].

OUTPUT

3. Scene-by-scene visual direction

4. On-screen evidence callouts

5. Technical explanation in plain language

7. 60-90 second recruiter version

8. YouTube title + description + chapters

10. Questions the portfolio AI should answer after the video

10. Audio Standard

• Use clean, consistent narration; no room echo.

• Keep background music subtle and duck it under speech.

• No music is acceptable if it improves clarity.

• Normalize levels across project videos so the series feels like one brand.

• Always provide captions and transcript; audio is not the only channel for information.

14. Automated Video Factory - Future State

Once the portfolio CMS is stable, the video workflow can become semi-automated. The goal is not one-click publishing; it is one-click preparation followed by human approval.

Step

Automation

1. Project update

CMS detects changed project version.

2. Script draft

AI generates updated narration, scene plan and short variants.

3. Evidence check

System validates URLs, asset presence and approved metrics.

4. Scene package

Generate slide content, title cards and callout text.

5. Avatar clips

Generate intro/transition/outro from approved script segments.

6. Editorial assembly

Create an editable project timeline/template.

7. Human approval

Creator watches full output and corrects narration/captions.

Upload master + derivatives and update CMS record.

Important: automated generation must never bypass human review for factual accuracy, privacy, URLs, pronunciation, licensing, or public claims.

18. Final Operating Model

One project in the CMS should generate one family of video assets: a deep-dive master, recruiter cut, social short and web poster/preview. The same verified source data should also power the project case study and the portfolio AI. This creates a “build once, explain everywhere” system rather than separate manual content for every channel.

Production rule: Never publish an AI-generated video simply because it looks good. Publish it only after the spoken claims, project behavior, evidence links, captions, permissions and licensing have been checked.
